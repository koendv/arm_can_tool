# hbpp — HarfBuzz Preprocessor for u8g2

## Synopsis

```
python3 hbpp.py [-v] FONT.ttf SIZE INPUT.c OUTPUT.h
```

## Description

`hbpp` is a one-pass C source preprocessor that shapes UTF-8 string literals
using the HarfBuzz text shaping engine and emits a C header containing
pre-shaped glyph arrays for use with `u8g2_DrawHB()` in the
[u8g2](https://github.com/olikraus/u8g2) graphics library.

Shaping is performed once at build time. The MCU iterates a pre-built byte
array — no HarfBuzz required on the target.

## Dependencies

- Python 3.8 or later
- [uharfbuzz](https://github.com/harfbuzz/uharfbuzz)

```
pip install uharfbuzz
```

## Arguments

| Argument | Description |
|----------|-------------|
| `FONT.ttf` | Font file (.ttf or .otf), relative to cwd |
| `SIZE` | Render size in pixels (integer) |
| `INPUT.c` | C source file to scan (read-only) |
| `OUTPUT.h` | C header file to generate |

## Options

| Option | Description |
|--------|-------------|
| `-v`, `--verbose` | Print font info and per-string results to stderr |

## Input Format

Two macro patterns are recognised. Both must appear one per line.
No multiline strings. No escaped quotes. `NAME` is letters, digits,
underscores, unique within the file per pattern.

### `HB_STR_NAME` — integer index

```c
HB_STR_NAME("utf-8 string")
```

The string is consumed by hbpp. The macro expands to a plain integer —
the index of the shaped array in the string table. Use where an integer
is needed, e.g. as a plain constant or with a hand-written `MUI_XYA`.

### `MUI_XYHB_NAME` — baked MUI form string element

```c
MUI_XYHB_NAME(id, x, y, "utf-8 string")
```

All four parameters consumed by hbpp. `id` is the muif identifier (always
`"HB"` in practice). `x` and `y` are integer literals (0–255). The string
is shaped and the macro expands to a raw byte string equivalent to
`MUI_XYA("HB", x, y, index)`, bypassing the `MUI_##` token-paste limitation
that prevents macro-valued arguments in `MUI_XYA`.

Use directly in MUI form strings:

```c
MUI_XYHB_NAMASTE("HB", 0, 15, "नमस्ते")
```

A `NAME` may appear in both patterns — they share one array and one index.

## Output Format

**Example** — output file `screen_hb.h`, two strings:

```c
/* Generated by hbpp.py — do not edit manually */
/* Source:  screen.c                             */
/* Command: python3 hbpp.py unifont.ttf 16 screen.c screen_hb.h */

#ifndef SCREEN_HB_H
#define SCREEN_HB_H

#include <stdint.h>

// न म स् त े
static const uint8_t _hb_NAMASTE_data[] U8X8_PROGMEM = {
  0x09, 0x28, 0x00, 0x00,  // 'U+2344'
  ...
  0x00, 0x00  // end
};

// H e l l o
static const uint8_t _hb_HELLO_data[] U8X8_PROGMEM = {
  ...
  0x00, 0x00  // end
};

static const uint8_t *screen_hb_strings[] = {
    _hb_NAMASTE_data,  /* 0 */
    _hb_HELLO_data,    /* 1 */
};

#define HB_STR_NAMASTE(z)                    0
#define MUI_XYHB_NAMASTE(id, x, y, s)       "A" "HB" "\x00" "\x0f" "\x00"
#define HB_STR_HELLO(z)                      1
#define MUI_XYHB_HELLO(id, x, y, s)         "A" "HB" "\x10" "\x20" "\x01"

/*
 * MUI callback — implement once in your project:
 *
 *   MUIF_RO("HB", mui_draw_hb)
 *
 *   uint8_t mui_draw_hb(mui_t *ui, uint8_t msg) {
 *       if (msg == MUIF_MSG_DRAW)
 *           u8g2_DrawHB(mui_get_u8g2(ui), ui->x, ui->y,
 *                       screen_hb_strings[ui->arg]);
 *       return 0;
 *   }
 */

#endif /* SCREEN_HB_H */
```

### Array format

Each entry: `<enc_hi> <enc_lo> <delta_x> <delta_y>` (4 bytes).
`delta_x` and `delta_y` are `int8_t` pen movements before drawing each glyph.
Terminated by `0x00 0x00`.

### Table name

Derived from the output filename stem. `screen_hb.h` → `screen_hb_strings[]`.
Two fonts, two invocations, two headers, two tables — no collision.

### `MUI_XYHB` expansion

`MUI_XYA(id, x, y, a)` expands to `"A" id MUI_##x MUI_##y MUI_##a`.
`MUI_##a` pastes before macro expansion, so a macro-valued `a` argument
fails. `MUI_XYHB_NAME` sidesteps this by emitting the equivalent byte
string directly:

```
"A"        — MUI command byte for XYA fields
"HB"       — muif id (2 chars)
"\xXX"     — x coordinate byte
"\xYY"     — y coordinate byte
"\xII"     — index byte
```

No MUI macro machinery involved at compile time.

## MUI Integration

Register one callback and one muif entry:

```c
MUIF_RO("HB", mui_draw_hb)
```

Use in form strings:

```c
MUI_XYHB_NAMASTE("HB", 0, 15, "नमस्ते")
MUI_XYHB_HELLO("HB", 0, 31, "Hello")
```

`u8g2_SetFontMode(&u8g2, 1)` (transparent mode) is required by `u8g2_DrawHB`.

## Error Handling

| Condition | Behaviour |
|-----------|-----------|
| Duplicate `NAME` in same pattern | Fatal; output not written |
| Font file not found | Fatal; exits immediately |
| `uharfbuzz` not installed | Fatal; exits immediately |
| x, y, or index outside 0–255 | Warning to stderr; output written |
| delta outside ±127 | Warning to stderr; output written |
| No macros found | Warning to stderr; output written |

## Limitations

- String literals must not span multiple lines.
- String literals must not contain escaped quotes (`\"`).
- One font per invocation. Two fonts → two invocations, two headers.
- Maximum 256 strings per file (`ui->arg` is `uint8_t`).
- `int8_t` delta constraint: glyph step limited to ±127 px.
  Not reached in practice at embedded display sizes (≤128 px).
- `x` and `y` in `MUI_XYHB_NAME` must be integer literals 0–255.
